# خادم روبي السحابي — ARRobot4

هذا خادم وسيط جاهز للنشر، وليس خادماً مستضافاً بالفعل. يلزم حساب API ومفتاح صالح مع الفوترة/الصلاحيات اللازمة لدى مزود النموذج.

## النشر
1. انشر هذا المجلد على خدمة تدعم Node.js 20+ أو Docker وتمنحك عنوان HTTPS عاماً.
2. في إعدادات متغيرات البيئة لدى الاستضافة، أضف `OPENAI_API_KEY` بقيمة المفتاح السري، و`ROBI_CLIENT_TOKEN` برمز عشوائي طويل لا يقل عن 32 حرفاً، و`OPENAI_MODEL=gpt-6-astra` (أو نموذجاً متاحاً لحسابك).
3. لا تضف المفتاح إلى التطبيق أو ملفات ZIP، ولا ترسله في المحادثة.
4. افتح `https://YOUR-DOMAIN/health`؛ يجب أن يظهر JSON يتضمن `ok: true`.
5. في روبي، قل «إعداد السحابة» وأدخل عنوان الأساس فقط مثل `https://YOUR-DOMAIN` ورمز `ROBI_CLIENT_TOKEN` نفسه ثم احفظ. سيختبر روبي `/health` ويستخدم `/v1/chat` للمحادثة.

## الواجهات
- `GET /health`: فحص صحة الخادم.
- `POST /v1/chat`: يستقبل `{ "message": "...", "previousResponseId": "resp_..." }` ويعيد `{ "text": "...", "responseId": "resp_...", "model": "..." }`.

يستخدم الخادم OpenAI Responses API ويحتفظ بمعرّف الرد السابق على العميل لمتابعة المحادثة. مفتاح API يبقى في الخادم. النموذج الافتراضي هو `gpt-6-astra`، لكن يجب أن يكون النموذج متاحاً لمشروع API الخاص بك؛ يمكن تغييره من متغير البيئة `OPENAI_MODEL`. قد تترتب رسوم على الاستخدام حسب حساب API والأسعار الحالية.

## ملاحظات أمنية
- استخدم HTTPS فقط في الإنتاج.
- احتفظ بسرية `ROBI_CLIENT_TOKEN` و`OPENAI_API_KEY`. رمز العميل يحد من الاستخدام غير المصرح به، لكنه ليس بديلاً عن حدود استخدام ومراقبة في بيئة الإنتاج.
- حد الطلبات في هذا المثال بدائي وذاكرته محلية للعملية؛ لا يعد بديلاً عن حماية استضافة إنتاجية.
